# 边境食堂 / Frontier Kitchen

一款以探索、发现、创造和经营为核心的单人 2D 俯视角游戏。项目设计以 [GAME_DESIGN.md](GAME_DESIGN.md) 为准；后续开发请先阅读该文件，再执行指定阶段。

## 当前进度

锅内烹饪已升级为用户提供规格中的完整规则表：125 条常规配方、13 条单一主料配方、118 个结果，支持恢复、效果、暴击、怪物精华及隐藏价值。规则范围和数据边界见 [docs/COOKING_RULES.md](docs/COOKING_RULES.md)。当前测试开局改为全部 160 条可用食材各 1 份。背包按 5 列 × 4 行分页，每页 20 格，共 8 页；耗尽的食材仍会隐藏。

已完成基础厨房与村庄，以及第一版烹饪和菜单交易。默认进入厨房，通过“出门”进入村庄，再点击“进入食堂”返回。厨房有灶台、备菜台、水槽与储物架；室外有食堂、菜园和小溪。所有领域状态由 GameSession 统一管理，切换场景保留库存、料理、菜单、食谱、金币和时间。初始时间第 1 天 08:00，金币 100，全部可用食材各 1 个。尚未实现移动、碰撞、时间流动、自动顾客和持久化存档。

## 烹饪与菜单

1. 厨房场景铺满浏览器视口。点击画面底部“使用灶台”或“菜单与食谱”，以覆盖弹窗打开对应界面；背包也使用覆盖弹窗。点击关闭、遮罩空白处或按 Escape 返回场景。
2. 选材按 5 列 × 4 行、每页 20 格翻页，翻页保留锅内选择。选择 1～5 份，可重复放入，同一食材不能超过库存。点击 × 可移除，清空锅内不消耗食材。
3. 点击“开始烹饪”，消耗本次选择的食材并获得 1 份料理。“煮”代表锅内料理入口，完整配方决定实际菜式。按原规格保留首次投料顺序进行贪心匹配，重复份数不提供额外种类槽位。相同配方与数值的料理叠加，暴击等不同结果分开保存。
4. 烹饪成功后弹出菜名、数量和原创程序绘制的料理图片，可直接“加入菜单”或“继续烹饪”。已制作列表同样可以加入菜单并记录食谱；不消耗成品，也不重复记录。当前图片按汤、串烧、甜品、药等类型绘制，尚非 118 道料理各自的正式美术。
5. 打开“菜单与食谱”，选择是否出售，填写大于零的整数售价并保存。输入草稿不影响已保存售价；库存为零时显示售罄。
6. 点击“模拟顾客购买”，按保存的售价卖出 1 份料理并立即获得金币。未上架或售罄时不能购买。顾客目前是显式测试按钮，尚无自动 NPC。

未拥有和耗尽的食材不会显示在背包或食材选择列表中。语言切换会更新料理名称和反馈，配方身份不会改变。

**当前进度只在本次运行中保留，刷新网页会重置料理、食谱和菜单；语言偏好单独保存。** 暂不提供无限补充食材按钮，初始食材耗尽后可刷新开始新一轮测试。

## 技术与结构

TypeScript 严格模式、Phaser 3、React、Vite、npm workspaces、Vitest。

```text
apps/web/                Web 入口、React 界面、Phaser VillageScene
packages/game-core/      平台无关类型、不可变状态快照、GameSession 订阅
packages/game-data/      食材、地点配置、初始状态及测试
packages/platform/       未来存档适配接口（尚未实现持久化）
GAME_DESIGN.md           完整设计与开发约束
```

GameSession 是唯一权威状态；React 通过 useSyncExternalStore 订阅，Phaser 通过同一实例读取和订阅。Game Core 不依赖 React、Phaser、DOM 或平台 API。Phaser 组件负责挂载、容器缩放及卸载销毁，兼容 React StrictMode。

## 开发

页面顶部的语言选项支持中文 / English，覆盖现有界面、食材、时间、厨房标签与食堂招牌。默认语言为英文，已有语言偏好保存在浏览器本地设置中，刷新后恢复；切换语言不会重建画布或重置游戏状态。英文源文案在 `apps/web/src/i18n/en.ts`，中文翻译在 `apps/web/src/i18n/zh-CN.ts`，语言订阅位于 `apps/web/src/i18n.ts`。新增可见文本时先添加英文键，再补齐中文翻译；TypeScript 会检查翻译键是否完整。数据配置也以英文为默认名称，游戏规则仍使用稳定 ID。

需要 Node.js 22.18+ 和 npm 10+。在项目根目录执行：

```bash
npm install
npm run dev
```

打开终端显示的本地地址（默认 http://127.0.0.1:5173）。点击“背包”可查看初始库存。窄屏自动调整界面，画布适应容器并考虑高 DPI。

```bash
npm run test       # Vitest 单元测试
npm run typecheck  # TypeScript 检查
npm run build      # 类型检查及生产构建
```

生产文件位于 `apps/web/dist/`。本轮未配置 lint、后端、云存储及移动/桌面打包。
